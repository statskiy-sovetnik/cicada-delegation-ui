# Договорённости по коду

## Типы

Типы не живут в файлах с кодом. Они лежат в `src/types/`, разбитые по
категориям: `position.ts` — контракт адаптера позиции. `src/types/index.ts`
реэкспортирует.

Исключение — типы, относящиеся к одной позиции: они лежат в папке этой позиции
(`src/positions/<позиция>/types.ts`), потому что за её пределами не нужны.

## Внешние API

Форматы внешних API описываются zod-схемами в `src/adapters/<сервис>/schema.ts`,
типы выводятся из них через `z.infer`. В `src/types/` их дублировать нельзя:
второго источника истины быть не должно.

Ответы **разбираются схемой**, а не кастуются. На основе данных Executor
строится то, что человек подписывает ключом, поэтому ответ не по контракту
должен быть назван сразу, а не всплыть неверной подписью.

Остальной код работает с выведенными типами и путей API не знает.

## Позиции

Общий код **не знает ни про одну конкретную позицию**. Ни адресов, ни ABI, ни
логики сверки в `App.tsx`, `Catalog.tsx` и прочем общем коде быть не должно.

Всё специфичное живёт в `src/positions/<позиция>/` за адаптером
`PositionAdapter` (`src/types/position.ts`):

```
src/positions/
  index.ts                 реестр и выбор адаптера по записи
  aerodromeWethVvv/
    adapter.ts             inspect: чтение состояния, сверка, remedies
    addresses.ts           адреса и ABI
    calldata.ts            разбор calldata операции
    types.ts               типы только этой позиции
```

Добавление позиции — новая папка и строка в реестре. Ничего за её пределами
менять не нужно.

Адаптер возвращает `PositionReport`: приговор, причину, проверки, разбор
операции для человека и `remedies` — действия, которыми делегатор чинит
непройденную проверку. Общий код рисует кнопку и отправляет транзакцию, не зная,
что именно вызывается.

Статус подписи в приговор не входит: он свойство записи, а не позиции, и
накладывается общим кодом.

## Подпись

Подписывается то, что интерфейс расшифровал **сам** из `GET /action/{id}/raw`.
Расшифровка из `GET /action/{id}` — только для показа: авторитетны сырые байты
(4.8 спецификации), и ошибка в декодере Executor не должна менять подписываемое.

## Прочее

Адреса и тела URL — в коде, секреты — в `.env` через виртуальный модуль
`virtual:ui-env` (см. `vite.config.ts`). `define` не использовать: в dev-режиме
Vite 8 его не подставляет.

Браузерные модальные окна (`alert`, `confirm`) не использовать — подтверждения
делаются внутри страницы.

Спецификация в `7702-demo/docs` — источник истины. Расхождение означает, что
надо поправить спецификацию, а не замолчать его.
